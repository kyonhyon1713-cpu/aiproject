## 1. ESP32-S3를 이용한 Edge Impulse 이미지 추론 실습

### 1.1 프로젝트 생성

Edge Impulse에 이미지 분류용 `EI project`를 만들고 `battery`와 `fan` 두 클래스를 사용했다. 이 프로젝트에서 카메라 이미지를 학습 데이터로 사용하고, 학습된 Arduino 추론 라이브러리를 XIAO ESP32-S3 Sense 펌웨어에 포함했다.

- Edge Impulse 프로젝트: `EI project` (ID `1078275`)
- 모델 종류: 이미지 분류
- 클래스: `battery`, `fan`
- 입력 이미지: 96 × 96 RGB 이미지
- 추론 라이브러리: `EI_project_inferencing`

### 1.2 이미지 데이터 수집

1. XIAO ESP32-S3 Sense에 카메라 AP 수집기 펌웨어를 업로드했다.
2. 스마트폰을 ESP32의 `bkh` AP에 연결했다.
3. 스마트폰 브라우저에서 `http://192.168.4.1`을 열었다.
4. 배터리와 선풍기를 각각 촬영하고 라벨을 구분했다.
5. 브라우저에서 약 150장 수준의 사진을 모아 ZIP으로 다운로드했다.
6. ZIP 파일을 `C:\arduinoTest\camera_dataset`에 저장했다.

노트북을 ESP32 AP에 직접 연결해 확인하면 노트북의 인터넷 연결이 끊길 수 있으므로, AP 접속과 브라우저 확인은 스마트폰으로 진행했다.

### 1.3 모델 학습

수집한 이미지를 Edge Impulse 프로젝트에 업로드하고 이미지 분류용 임펄스를 구성했다. 이미지 전처리와 전이학습 모델을 사용해 `battery`와 `fan`을 구분하도록 학습했다.

학습된 모델은 Arduino 라이브러리 형태로 내려받아 다음 추론 스케치에 연결했다.

```text
C:\arduinoTest\xiao_webcam_ap_infer\xiao_webcam_ap_infer.ino
C:\arduinoTest\xiao_webcam_ap_infer\libraries\EI_project_inferencing
```

ESP32-S3 Sense에서 카메라 모델을 실행할 때는 모델 메모리 확보를 위해 PSRAM을 사용했다. Arduino CLI 작업에서는 XIAO ESP32-S3 보드 설정과 PSRAM 옵션을 컴파일·업로드 과정에 함께 적용했다.

카메라 추론 스케치의 컴파일·업로드 흐름은 다음과 같다. 모델 라이브러리를 교체한 직후에는 `--clean`으로 오래된 컴파일 캐시를 제거한다.

```powershell

$fqbn = 'esp32:esp32:XIAO_ESP32S3'

arduino-cli compile --clean --fqbn $fqbn `
  --board-options PSRAM=opi $sketch

arduino-cli upload -p COM11 --fqbn $fqbn `
  --board-options PSRAM=opi $sketch
```

### 이미지 추론의 핵심 코드 흐름

실제 스케치는 카메라 프레임을 받아 RGB565 픽셀을 RGB 값으로 변환하고, Edge Impulse가 요구하는 feature buffer에 넣은 뒤 `run_classifier()`를 호출한다.

```cpp
camera_fb_t *fb = esp_camera_fb_get();
const int W = EI_CLASSIFIER_INPUT_WIDTH;
const int H = EI_CLASSIFIER_INPUT_HEIGHT;

for (int y = 0; y < H; y++) {
  for (int x = 0; x < W; x++) {
    // 카메라 장착 방향에 맞춘 시계 방향 회전 보정
    int sx = y * fb->width / H;
    int sy = fb->height - 1 - (x * fb->height / W);
    uint16_t px = ((const uint16_t *)fb->buf)[sy * fb->width + sx];

    uint8_t r = ((px >> 11) & 0x1F) << 3;
    uint8_t g = ((px >> 5) & 0x3F) << 2;
    uint8_t b = (px & 0x1F) << 3;
    features[y * W + x] = (float)((r << 16) | (g << 8) | b);
  }
}
esp_camera_fb_return(fb);

signal_t signal;
signal.total_length = W * H;
signal.get_data = &get_feature_data;
ei_impulse_result_t result = {0};
EI_IMPULSE_ERROR status = run_classifier(&signal, &result, false);
```

카메라 초기화 뒤에는 자동 화이트밸런스가 안정될 시간을 주기 위해 실제 추론 전에 프레임을 여러 장 버린다. 현재 스케치는 warm-up 프레임 10장을 사용한다.

### 1.4 ESP32-S3에서 추론 실행

추론 펌웨어는 다음 기능을 제공한다.

- `bkh` AP를 생성한다.
- `http://192.168.4.1`에서 실시간 카메라 화면을 보여 준다.
- `/classify` 요청마다 새 프레임을 촬영해 추론한다.
- 화면에 최종 라벨과 클래스별 confidence를 퍼센트로 표시한다.
- `battery`와 `fan`의 확률 막대를 브라우저에 표시한다.
- 추론 시간도 `dsp_ms`, `nn_ms`로 표시한다.

카메라 모듈의 실제 방향과 영상 좌표가 맞지 않아 회전 보정을 적용했다. 현재 스케치는 프레임을 시계 방향으로 보정한 뒤 Edge Impulse 모델에 전달한다.

### 1.5 실습 과정에서 배운 점

- 카메라 분류 모델은 물체 자체뿐 아니라 배경색, 밝기, 그림자, 촬영 각도에도 영향을 받는다.
- 흰색 배터리가 밝은 배경과 비슷하면 `fan`으로 잘못 분류될 수 있다. 각 클래스에 다양한 배경·거리·조명 조건의 데이터를 추가해야 한다.
- 클래스별 데이터 수를 비슷하게 유지해야 한쪽 클래스에 치우친 모델을 줄일 수 있다.
- XIAO ESP32-S3 Sense 카메라 추론에는 PSRAM과 충분한 Tensor arena가 중요하다.
- AP 모드는 노트북 인터넷 연결에 영향을 줄 수 있으므로, 로컬 웹 페이지 검증은 스마트폰으로 하는 것이 편리하다.
- 브라우저에 confidence를 함께 표시하면 단순히 최종 라벨만 보는 것보다 모델의 불확실성을 확인하기 쉽다.

## 2. 여러 센서 테스트

세 센서는 모두 XIAO ESP32-S3의 같은 I2C 버스에 연결해 주소를 확인했다. 센서 모듈의 실제 핀 순서는 제품마다 다를 수 있으므로 기판에 인쇄된 핀 이름을 기준으로 연결했다.

| 센서 | 형태·I2C 주소 | 역할 | 테스트 결과 |
| --- | --- | --- | --- |
| BH1750 / GY-302 | 5핀, `0x23` | 주변 밝기를 lux로 측정 | 연결 확인, 조도 값 정상 출력. 직접 측정에서 약 75~86 lux 범위 확인 |
| BME280 | 4핀, `0x76` | 온도·기압·습도 측정 | CHIP_ID `0x60` 확인. 약 22.3 °C, 1006.7 hPa, 48.2% RH 출력 |
| BNO055 | 8핀, `0x29` | Euler 자세각, 가속도, 자이로, 온도, 보정 상태 측정 | `0x29` 응답과 측정값 출력 확인. 자세 보정 상태는 센서를 고정하고 추가 보정할 수 있음 |

### I2C 주소 정리

| 장치 | 오늘 확인한 주소 | 가능한 대체 주소 | 주소 설정 핀·조건 | 주소의 의미 |
| --- | ---: | ---: | --- | --- |
| BH1750 / GY-302 | `0x23` | `0x5C` | `ADDR`를 GND/미연결이면 `0x23`, 3V3이면 `0x5C` | 조도 측정 |
| BNO055 | `0x29` | `0x28` | 모듈의 ADR/COM3 설정에 따라 결정 | 자세·관성 측정 |
| BME280 | `0x76` | `0x77` | SDO/ADR가 LOW이면 보통 `0x76`, HIGH이면 `0x77` | 환경 측정 |

따라서 오늘 확인한 세 주소 `0x23`, `0x29`, `0x76`은 서로 겹치지 않는다. I2C 주소는 7비트 주소 표기이며, `0x00`~`0x02`와 `0x78`~`0x7F` 같은 예약 범위는 일반 센서 주소로 사용하지 않는다.

### I2C 스캐너 코드

센서가 연결됐는지는 먼저 `Wire.endTransmission()` 응답으로 확인했다. 스캐너는 실제 센서 측정 전에 배선 오류와 주소 설정 오류를 빠르게 구분하는 데 유용하다.

```cpp
Wire.begin(5, 6);          // SDA=D4/GPIO5, SCL=D5/GPIO6
Wire.setClock(100000);     // 100 kHz

for (uint8_t address = 0x03; address <= 0x77; address++) {
  Wire.beginTransmission(address);
  if (Wire.endTransmission() == 0) {
    Serial.printf("I2C device found: 0x%02X\n", address);
  }
}
```

### 공통 I2C 연결

| XIAO ESP32-S3 | 센서 공통 연결 |
| --- | --- |
| 3V3 | VCC 또는 센서 모듈의 3.3V 입력 |
| GND | GND |
| D4 / GPIO5 | SDA |
| D5 / GPIO6 | SCL |

각 센서의 I2C 주소가 달라 한 버스에서 함께 사용할 수 있다. 여러 센서를 추가할 때는 주소가 겹치는지 먼저 I2C 스캐너로 확인해야 한다.

## 3. BH1750(GY-302) 조도센서

### 3.1 연결 방법

GY-302는 BH1750 칩을 장착한 조도센서 모듈이다. 모듈의 핀 순서는 제품마다 다를 수 있으므로 `VCC`, `GND`, `SDA`, `SCL`, `ADDR` 표기를 확인한다.

| GY-302/BH1750 | XIAO ESP32-S3 |
| --- | --- |
| VCC | 3V3 |
| GND | GND |
| SDA | D4 / GPIO5 |
| SCL | D5 / GPIO6 |
| ADDR | GND 또는 미연결 → `0x23` |

`ADDR`를 3V3에 연결하면 일반적으로 주소가 `0x5C`로 바뀐다. 이번 실습에서는 `0x23`을 사용했다. 센서 모듈은 3.3V 전원과 3.3V I2C 신호 기준으로 연결했다.

### 연결 확인 체크표

| 확인 순서 | 정상 조건 | 문제가 있을 때 확인할 것 |
| --- | --- | --- |
| 전원 | VCC=3V3, GND 공통 | 모듈의 VCC/VIN 표기와 전압 범위 |
| I2C 선 | SDA=D4/GPIO5, SCL=D5/GPIO6 | SDA/SCL를 서로 바꾸지 않았는지 |
| 주소 | 스캐너에서 `0x23` 응답 | ADDR가 3V3에 연결되지 않았는지 |
| 센서 명령 | `0x01` → `0x07` → `0x10` 순서 성공 | 배선, 풀업, 전원, 다른 장치와의 주소 충돌 |
| 측정값 | 2바이트 수신 후 lux 출력 | `Wire.requestFrom()` 반환 바이트 수 |

### 3.2 데이터 읽기

테스트 코드는 외부 BH1750 라이브러리 없이 `Wire`로 레지스터 명령을 전송했다.

1. `0x01` 명령으로 센서를 켠다.
2. `0x07` 명령으로 측정 상태를 초기화한다.
3. `0x10` 명령으로 연속 고해상도 측정을 시작한다.
4. 약 180 ms 후 2바이트 측정값을 읽는다.
5. 원시값을 `1.2`로 나누어 lux로 변환한다.
6. 1초마다 값을 출력한다.

핵심 계산은 다음과 같다.

```cpp
uint16_t raw = ((uint16_t)Wire.read() << 8) | Wire.read();
float lux = raw / 1.2f;
```

동일한 읽기 과정을 함수로 표현하면 다음과 같다.

```cpp
bool readLux(float &lux) {
  const uint8_t received = Wire.requestFrom((uint8_t)0x23, (uint8_t)2);
  if (received != 2 || Wire.available() < 2) return false;

  const uint16_t raw = ((uint16_t)Wire.read() << 8) | Wire.read();
  lux = raw / 1.2f;
  return true;
}
```

### 3.3 Edge Impulse 센서 프로젝트 생성

이미지 프로젝트와 센서 시계열 프로젝트를 분리했다. BH1750 데이터는 이미지 프로젝트가 아닌 별도의 `EI sensor project`에 업로드했다.

- Edge Impulse 프로젝트: `EI sensor project` (ID `1078538`)
- 입력 축: `lux`
- 샘플링 주기: 1초, 1 Hz
- 한 샘플 길이: 30개 값, 약 30초
- 라벨: `indoor`
- 임펄스 입력 창: 30,000 ms
- Window increase: 30,000 ms
- DSP: Raw data
- 학습 블록: Anomaly Detection (K-means), cluster count 3

```cpp
// 브라우저가 1초마다 GET /data를 호출한다.
String json = "{\"ok\":true,\"address\":23,\"lux\":" +
              String(lux, 3) + "}";
server.send(200, "application/json", json);
```

브라우저는 이 값을 모아 샘플 하나가 완성될 때마다 다음 형식의 CSV를 만든다.

| 필드 | 예시 | 의미 |
| --- | --- | --- |
| `timestamp` | `0`, `1000`, `2000` | 샘플 시작부터의 경과 시간(ms) |
| `lux` | `602.500` | BH1750 측정 조도(lux) |
| 샘플 간격 | 1000 ms | 1 Hz |
| 샘플 길이 | 30행 | 약 30초 |

Edge Impulse 업로드 후의 데이터 분할은 다음과 같다.

| 구분 | 개수 | 라벨 | 용도 |
| --- | ---: | --- | --- |
| training | 15 | `indoor` | K-means 정상 패턴 학습 |
| testing | 5 | `indoor` | 학습하지 않은 샘플의 score 확인 |
| 전체 | 20 | `indoor` | 이번 실습 데이터셋 |

CLI 업로드는 API 키를 문서에 직접 기록하지 않고 환경 변수나 로컬 비밀 저장소에서 읽어 사용한다. 파일을 한 개씩 넘기면 Windows PowerShell에서도 경로가 합쳐지는 문제를 피할 수 있다.

```powershell
$apiKey = '<EI_API_KEY>'  # 실제 키는 문서·GitHub에 기록하지 않는다.
$dataset = 'C:\arduinoTest\sensorTest\bh1750_dataset\bh1750_data'

Get-ChildItem -LiteralPath $dataset -Filter '*.csv' | Sort-Object Name |
  ForEach-Object {
    edge-impulse-uploader --api-key $apiKey `
      --category split $_.FullName
  }
```

### 3.5 BH1750 모델 학습·테스트 결과

15개 training 샘플로 정상적인 `indoor` 조도 패턴을 학습하고, 5개 testing 샘플을 모델 테스트에 사용했다. 테스트 작업 자체는 성공했지만 모든 테스트 라벨이 `indoor`이므로 anomaly/no-anomaly 정확도와 F1 점수는 계산되지 않았다.

| 테스트 샘플 | Anomaly score | 해석 |
| --- | ---: | --- |
| `indoor.0007` | -0.80 | 정상 범위 |
| `indoor.0013` | 1.01 | 임계값 0.3 초과, 이상 후보 |
| `indoor.0017` | -0.10 | 정상 범위 |
| `indoor.0018` | -0.17 | 정상 범위 |
| `indoor.0019` | -0.03 | 정상 범위 |

이번 데이터는 `indoor` 한 가지 상태만 있으므로 이상탐지 모델에 적합했다. 어두운 곳, 밝은 곳, 실외 등 조도 상태를 분류하는 모델을 만들려면 `dark`, `bright`, `outdoor`처럼 서로 다른 라벨의 데이터를 추가로 수집해야 한다.

## 4. ESP32-S3와 Edge Impulse의 동작 흐름

### 4.1 이미지 모델 흐름

이미지 모델은 Edge Impulse가 학습을 담당하고, 학습이 끝난 뒤에는 생성된 Arduino 라이브러리가 ESP32-S3 내부에서 추론을 담당한다. 추론할 때 인터넷이나 Edge Impulse 서버에 매번 접속하지 않는다.

```text
[Edge Impulse Studio]
  이미지 업로드 → 이미지 임펄스 구성 → 전이학습 → Arduino 라이브러리 다운로드
                                      ↓
[ESP32-S3 Sense]
  카메라 프레임 → 회전·색상 변환 → run_classifier() → battery/fan 확률
                                      ↓
[ESP32-S3 웹 서버]
  /jpg, /classify → 스마트폰 브라우저에 영상·confidence 표시
```

즉, Edge Impulse는 모델을 만드는 단계에 사용되고, ESP32-S3는 배포된 모델을 실행하는 단계에 사용된다. 이 구조 덕분에 카메라 추론 결과는 AP에 연결된 스마트폰에서 바로 확인할 수 있다.

### 4.2 센서 모델 흐름

BH1750은 먼저 측정값을 CSV로 만들고, Edge Impulse에서 시계열 임펄스를 구성·학습·테스트한다.

```text
[BH1750]
  I2C raw 2바이트 → lux 변환 → 1초 간격 측정
                                      ↓
[ESP32-S3 AP logger]
  /data JSON → 브라우저에서 30개 값 수집 → timestamp,lux CSV
                                      ↓
[Edge Impulse]
  CSV 업로드 → training/testing 분할 → Raw data feature 생성
  → K-means anomaly 모델 학습 → testing 샘플 anomaly score 확인
```

카메라와 달리 이번 BH1750 모델은 아직 ESP32-S3에 다시 배포하지 않았고, Edge Impulse의 테스트 화면/API에서 모델 결과를 확인하는 단계까지 진행했다.

## 5. 오늘 실습하며 알게 된 점과 주의사항

| 주제 | 알게 된 점 | 주의사항 |
| --- | --- | --- |
| I2C 배선 | SDA/SCL은 같은 버스에 병렬로 연결하고 주소로 장치를 구분한다. | 전원은 3.3V 기준으로 연결하고, 주소가 겹치는 센서는 동시에 사용하지 않는다. |
| 센서 주소 | BH1750=`0x23`, BNO055=`0x29`, BME280=`0x76`로 오늘은 충돌이 없었다. | 주소는 모듈의 ADDR/ADR/SDO 상태에 따라 달라질 수 있으므로 스캐너로 먼저 확인한다. |
| 전원·신호 | GND를 보드와 센서가 공유해야 I2C 통신이 안정적이다. | 모듈에 `VIN`이 있어도 I2C 풀업 전압이 5V가 되는지 확인한다. XIAO GPIO에 5V 신호를 직접 넣지 않는다. |
| 카메라 메모리 | ESP32-S3 Sense의 카메라 모델은 PSRAM과 Tensor arena가 중요하다. | 모델 라이브러리를 바꾸면 첫 컴파일에 `--clean`을 사용하고 PSRAM 옵션을 컴파일·업로드에 모두 적용한다. |
| 카메라 방향 | 센서가 장착된 방향과 화면 좌표가 다를 수 있다. | 회전 보정 전후로 같은 물체를 추론해 confidence가 더 높은 방향을 선택한다. |
| 카메라 데이터 | 배경, 조명, 물체 크기, 촬영 각도가 분류 결과에 영향을 준다. | 한 가지 배경만 사용하지 말고 클래스별로 다양한 조건을 수집한다. 흰색 배터리처럼 배경과 비슷한 물체는 특히 주의한다. |
| AP 테스트 | ESP32 AP에 노트북을 연결하면 노트북 인터넷이 끊길 수 있다. | AP 접속과 브라우저 확인은 스마트폰으로 하고, 노트북의 Wi-Fi 상태를 모델 오류로 오해하지 않는다. |
| 시리얼 포트 | USB CDC 포트를 열 때 보드가 리셋될 수 있다. | 업로드 전에 다른 시리얼 프로그램을 닫고, 포트가 바뀌었으면 `arduino-cli board list`로 다시 확인한다. |
| Edge Impulse 라벨 | 파일명 `indoor.0001.csv`에서 `indoor` 라벨을 일관되게 유지할 수 있다. | 분류 모델은 최소 두 개 이상의 의미 있는 클래스가 필요하다. 한 라벨 데이터에는 이상탐지가 더 적합하다. |
| 테스트 지표 | `indoor`만 있는 anomaly 테스트는 score는 나오지만 F1/정확도가 계산되지 않았다. | 평가 지표가 필요하면 testing 데이터를 `anomaly`와 `no anomaly`로 라벨링하거나, 분류 목적에 맞는 여러 클래스 데이터를 추가한다. |
| 인증 정보 | API 키와 AP 비밀번호는 코드·문서에 남으면 외부에 노출될 수 있다. | GitHub에 올릴 때는 API 키를 절대 커밋하지 않고, 비밀번호도 공개 문서에서 제거하거나 별도 로컬 설정으로 관리한다. |

### 재현할 때의 최소 점검 순서

```text
1. arduino-cli board list                    # 실제 COM 포트 확인
2. I2C 스캐너 실행                           # 0x23/0x29/0x76 응답 확인
3. 센서 단독 예제 실행                        # 측정값이 안정적인지 확인
4. AP logger 실행                             # 스마트폰에서 /data 확인
5. CSV의 timestamp 간격·라벨·행 수 확인
6. Edge Impulse에 training/testing 업로드
7. 임펄스 → feature 생성 → 학습 → model testing
8. 카메라 모델은 PSRAM·방향 보정·confidence를 함께 확인
```
